# AI 编码工程闭环

## 1. 理解

先定位目标代码、现有约定、测试方式和风险边界。应明确已知事实与待确认问题，避免根据文件名或局部代码猜测系统行为。

## 2. 计划

使用任务契约写清：目标、非目标、影响范围、接口/数据变化、验收标准和回滚方式。变更较大时先列出计划，获得确认后再实现。

## 3. 实现

一次只实施一个可验证的变更。优先遵循仓库原有结构、命名、依赖和测试习惯；不要把未经请求的重构混入功能修改。

## 4. 验证

按风险选择验证组合：格式化、静态检查、类型检查、单元测试、集成测试、构建、手动验收。失败时记录原因并回到对应步骤，而不是用“看起来合理”代替验证。

## 5. 审查

使用审查清单检查：需求是否完整响应、边界条件、错误处理、权限与数据安全、性能影响、可观测性，以及是否引入无关改动。

## 6. 记录

记录实际变更、验证结果、已知限制和后续事项。对可复用的约定补入仓库文档，减少下一次任务的重复解释。
